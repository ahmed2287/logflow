# لوحة إدارة اللوجات

داشبورد PHP بسيطة لعرض ملفات اللوجات من مسار على السيرفر، وحذف الأقدم من عدد أيام تحدده يدويًا،
مع سجل نشاط يوضح **من حذف ماذا ومتى**.

## المميزات

- **لوجن متعدد المستخدمين** — كلمات المرور مخزّنة بـ bcrypt، وصلاحيتان: `مدير` و `مشاهدة فقط`.
- **عرض اللوجات** — قائمة بالملفات مع الحجم وتاريخ التعديل والعمر بالأيام، بحث، وترتيب.
- **قارئ لوج** — يعرض آخر N سطر (بدون تحميل الملف كله)، تلوين ERROR/WARN/INFO، وتلوين نص البحث.
- **تنظيف بالتاريخ (سطور، مش ملفات)** — تختار تاريخًا وملفًا معينًا (أو كل الملفات)، فتُحذف
  **السطور** الأقدم من التاريخ من داخل الملفات نفسها. معاينة بعدد السطور والحجم قبل الحذف،
  ثم تأكيد مزدوج بإعادة إدخال التاريخ. السطور بدون تاريخ (تكملة Stack Trace مثلًا) تتبع آخر
  سطر مؤرَّخ قبلها. الصيغ المدعومة: `2026-08-25`، `25/08/2026`، `25/Aug/2026` (nginx)،
  `[25-Aug-2026]` (PHP)، و `Aug 25 10:00` (syslog).
- **سجلّا نشاط** — «سجل نشاطي» لكل مستخدم (يرى نشاطه هو فقط)، و«سجل نشاط اللوحة» للمدير
  (يرى الجميع). كل عملية (دخول، عرض، تحميل، حذف، تنظيف، تعديل إعدادات) مسجّلة باسم المستخدم
  و IP والملفات المتأثرة. المدير يرى الجميع، والمشاهد يرى نفسه فقط.
- **مسارات متعددة بأسماء** — تضيف أكتر من مجلد لوجات من الإعدادات، كل واحد باسم خاص به،
  وتتنقل بينها بتبويبات في اللوحة. أنماط الملفات وباقي الإعدادات مشتركة.
- **عربي / English** — زرار في القايمة الجانبية يبدّل لغة الواجهة والاتجاه (RTL/LTR).
  الاختيار بيتحفظ في كوكي. العربي هو الأساس، والترجمات في `src/lang_en.php`
  (أي نص جديد بيتضاف بـ `__('النص العربي')` ومفتاحه هو النص نفسه).

## التشغيل

### تطوير
```bash
./serve.sh                 # http://127.0.0.1:8080
./serve.sh 0.0.0.0 8080    # متاح على الشبكة
```

أول مرة تفتح اللوحة هتطلب منك إنشاء **حساب المدير الأول**، وبعدها تحدد مسار اللوجات من الإعدادات.

### nginx (مركّب ومظبوط بالفعل على الجهاز ده)

اللوحة شغّالة على **http://almasrylog.test**

| | |
|---|---|
| مجلد المشروع | `/var/www/html/log-manager` |
| كونفج nginx | `/etc/nginx/sites-available/local-almasrylog.conf` (نسخة منه في `nginx.conf.example`) |
| مُفعَّل عن طريق | symlink في `/etc/nginx/sites-enabled/` |
| الدومين | `almasrylog.test` → سطر في `/etc/hosts` |
| php-fpm | `unix:/run/php/php8.3-fpm.sock` (pool شغّال كـ `hamdy`، ونفس مستخدم nginx) |
| لوجات nginx | `/var/log/nginx/almasrylog.{access,error}.log` |

بعد أي تعديل على الكونفج:
```bash
sudo nginx -t && sudo systemctl reload nginx
```

الـ docroot هو `public/` تحديدًا، فـ `data/` (المستخدمين وسجل النشاط) و `src/` و `views/` و `cli/`
كلهم فوق مستوى الـ docroot ومش قابلين للوصول من الويب.

> لو نقلت المشروع لسيرفر تاني بمستخدم PHP مختلف (`www-data` مثلًا)، لازم `data/` تكون
> قابلة للكتابة منه: `chown -R www-data:www-data data/ && chmod 750 data/`

### تطوير بدون nginx
`./serve.sh` بيشغّل سيرفر PHP المدمج على `127.0.0.1:8080` — مفيد لو عايز تجرّب بسرعة.

## سطر الأوامر

مفيد لو اتقفلت برّه اللوحة، أو لجدولة التنظيف بـ cron.

```bash
php cli/manage.php users                          # قائمة المستخدمين
php cli/manage.php add ahmed 'Pass1234' admin     # إضافة مستخدم
php cli/manage.php passwd ahmed 'NewPass1234'     # تغيير كلمة المرور
php cli/manage.php delete ahmed                   # حذف مستخدم
php cli/manage.php set-dir /var/log/myapp myapp   # إضافة/تعديل مسار باسم
php cli/manage.php sources                        # قائمة المسارات
php cli/manage.php cleanup 30 --dry-run           # معاينة بدون حذف (كل المسارات)
php cli/manage.php cleanup 30 --src=myapp         # حذف فعلي من مسار واحد (يُسجَّل باسم "cli")
php cli/manage.php audit 50                       # آخر 50 عملية
```

### تنظيف تلقائي بـ cron
```cron
# كل يوم 3 صباحًا: احذف اللوجات الأقدم من 30 يوم
0 3 * * * php cli/manage.php cleanup 30 >> /var/log/almasrylog-cron.log 2>&1
```

## الأمان

- كل مسار جاي من المتصفح بيتحقق منه بـ `realpath()` ولازم يكون **جوه مجلد اللوجات** — أي محاولة
  `../` أو مسار مطلق مرفوضة (`src/logs.php:log_resolve`).
- الملفات اللي مش مطابقة لأنماط الإعدادات مش قابلة للعرض ولا الحذف، حتى بمسار مباشر.
- CSRF token على كل POST؛ session cookie بـ `HttpOnly` + `SameSite=Lax` (+`Secure` على HTTPS).
- إيقاف مؤقت 5 دقائق بعد 5 محاولات دخول فاشلة، والمحاولات الفاشلة مسجّلة في سجل النشاط.
- تنظيف السطور محمي بتأكيد مزدوج: لازم تعيد إدخال التاريخ نفسه.
- الـ symlinks اللي بتشاور برّه مجلد اللوجات بتُتجاهل ومش بتُتبَع.

## الملفات

```
public/index.php          الراوتر — كل الطلبات بتمر منه
public/assets/            style.css + app.js (بدون أي مكتبات خارجية)
src/bootstrap.php         الإعدادات والمسارات والدوال المشتركة
src/auth.php              المستخدمون والصلاحيات واللوجن
src/logs.php              قراءة/سرد/حذف اللوجات + التحقق من المسارات
src/audit.php             سجل النشاط (JSON Lines)
src/csrf.php              حماية CSRF
views/                    صفحات العرض
cli/manage.php            أدوات سطر الأوامر
data/                     users.json · config.json · audit.log  ← لا تعرّضها للويب
```

## ملاحظات

- `data/audit.log` بيكبر مع الوقت (سطر JSON لكل عملية). لو وصل لعشرات الميجابايت اعمله rotate:
  ```bash
  mv data/audit.log data/audit-$(date +%F).log && touch data/audit.log
  ```
- الحذف **نهائي** (`unlink`) — مفيش سلة مهملات. لو محتاج استرجاع، خُد نسخة احتياطية قبل التنظيف.
- الملفات الأكبر من `max_view_mb` بتُعرض جزئيًا فقط (آخر أسطر) — حمّلها لمراجعتها كاملة.
